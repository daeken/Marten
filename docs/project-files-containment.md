# Files containment review: keep Darwin serving disabled

## Required guarantee

Files remains read-only and sees the live contents of an exact, approved project binding. It is not a publisher, snapshot store, or agent worktree browser. Device authorization, root approval, entry selection and filesystem containment are separate checks. A stale handle must never authorize a replacement entry. Reads always use the already-open regular file; they must not switch to another object after it moves. A final re-resolution and revision check rejects observed moves and changes before delivery of the last chunk, but cannot promise an atomic copy of a file with concurrent writers. Do not emit the final chunk on failure, and require the client to discard incomplete transfers.

Assume the host administrator and kernel are trusted, but ordinary workspace writers can concurrently rename and replace entries. The privileged mount test belongs in a disposable VM, not on the active Mac. A string path, vnode spelling, equal `st_dev`, or a successful post-open stat is not an atomic precondition on the byte-bearing open.

## Darwin decision

Keep the test-only resolver gate in #74. The draft uses a verified directory descriptor, full relative resolution with `O_RESOLVE_BENEATH | O_NOFOLLOW_ANY`, metadata-only inspection, local APFS and identity/revision checks. Current tests verify stable and replaced entries. They do **not** show either of these stronger properties:

1. The kernel rejects every nested mount during the same lookup that selects the object. A loop that stats parents, then does another lookup from the root, is not equivalent. `st_dev` is a filesystem/device comparison, not a mount boundary guarantee.
2. The byte-bearing open can acquire read access to **the exact regular vnode previously checked**, without another workspace-name lookup that can select a special file. `O_NONBLOCK` and checking the returned descriptor before reading are useful defenses but are not a regular-file-only open. `proc_pidfdinfo` is corroborating metadata, not a containment primitive.

Do not ship a best-effort realpath/lexical check, a pathname reopen with additional checks, a sandbox rule that matches path spellings, or a privileged helper as a substitute. Local APFS and unprivileged operation reduce exposure but don't prove the contract. A Darwin implementation is viable only after identifying and validating supported kernel primitives (or an equivalent isolation design) that enforce both properties. An immutable export would change live Files semantics; keep it a separate artifact/publish feature, not a fallback.

## Proposed owner-controlled existing-folders contract (approval required)

**Decision for Sera:** Is a pilot limited to exact existing checkouts with owner-controlled ancestry, namespace writers and mount topology worthwhile? If agents sharing the service UID are adversaries, pick genuinely isolated roots/credentials or keep Files off. Ownership and POSIX permission checks cannot distinguish processes sharing a UID. This is not a proposal to trust every configured binding or to turn Files into artifact publishing.

- **Approved parent is a boundary, not a grant.** Local operator pins a narrow physical parent on an eligible local volume and separately grants a particular existing binding below it to one project. No broad home/volume roots, protected Marten home/backups/exports overlaps, managed worktrees, or arbitrary paths. Resolve any intentional binding alias against the exact approved target; reject aliases into protected trees and reject physical ancestors/targets that cannot be established, including a missing protected location unless an approved existing parent bounds it. Require a separately verified control policy for the lexical alias chain, anchor and its physical ancestors, including ACLs, group/other write, mount administration, and service/agent credentials. If there is no practical way to establish control, deny. A trusted parent does not make an untrusted writable subtree safe; all parties able to replace project entries or graft mounts must be trusted or isolated. Document which trusted software may edit ordinary files. No auto-repin after a move, mount change, or replacement.
- **Typed, pinned opens.** Use a platform-specific adapter with ABI/runtime tests and typed root and mount identities (filesystem/volume identity + mount-instance identity + directory dev/ino/birth/generation where supported). Do not persist a string made only from `st_dev` and inode as a mount proof. Revalidation includes project/binding mapping, root path identity, and a verified physical ancestry/protected boundary. Separate checked directory opens, non-activating entry inspection, and regular-file byte acquisition. Keep kernel beneath/no-link protections, no nested mounts, reject special/hard-linked objects, and revalidate the same descriptor. For arbitrary untrusted writers, the two Darwin gaps above remain blockers. Under an approved controlled-namespace contract, an invariant that mounts and special nodes cannot be introduced must be enforced by the deployment and verified independently; it cannot be inferred by periodically checking paths. Keep Darwin disabled until such an invariant or stronger primitives are demonstrated.
- **Prepare before publishing.** Read the bounded prefix/full file into a request-scoped private staging object, never an agent-writable or shared location; use bounded memory or an anonymous/private temporary file with deterministic deletion. Reserve storage before reading; verify exact observed byte count and descriptor revision before/after, and re-resolve the selected node and grant before preparing a success response. Do not expose staged bytes/handles or send success headers until publication admission. This is temporary transport staging for a fresh request, not retained or user-visible file versions. Compare before/after directory identity/revision across the bounded scan; page only a bounded metadata snapshot with stable snapshot/row IDs and deterministic ordering. Recheck directory/current grant on every page; changed/expired snapshots mean refresh. Each file row carries the observed revision; reopening checks it, never substitutes current contents under a stale handle. Revision results describe observations, not atomic snapshots of concurrently edited files.
- **Publication and revocation.** Give each grant a generation; bind handles and snapshots to grant, project and paired credential ID/generation. At a short publication commit shared with grant removal and credential revocation, verify both are still active and that prepared metadata/bytes match the grant and expected revision. `CancellationToken.IsCancellationRequested` alone is insufficient: current pairing revocation removes the credential under a lock and cancels outside it. Use authoritative credential membership and coordinate both authorization transitions with permit commit; no filesystem/transmission while holding the lock. A revoke/removal that wins the commit race denies publication; one after commit cancels pending delivery, invalidates handles and aborts incomplete responses. Bytes already handed to transport/export cannot be recalled; do not promise otherwise. Errors and denied publishes release all reservations and staging, without exposing host paths or entry names.
- **Fairness is a resource contract.** Independently bound queue length, per-device and global in-flight work, scan entries/elapsed time, snapshots/handles/encoded metadata, staged bytes/open descriptors, output slots and deadlines. Charge reservations before scheduling, including staging and slow sends, and release on abort/expiry without waiting for that device to return. Schedule round-robin across devices (or reserve capacity), with at most one selection/scan worker per device and a separate bounded delivery lane so slow consumers cannot exhaust scanners. Reject over quota with retry; never add hidden unbounded queues. A deadline is not a guarantee about synchronous backend syscalls: limit occupancy and consider an isolated worker with enforceable shutdown for a nonresponsive filesystem. Record aggregate counters without paths, names, handles or credentials.
- **Test actual authority, not a substitute Host.** Exercise production route registration/security and a scratch HTTPS proxy path with the right SNI/canonical authority, plus the real loopback listener authority. Prove aliases, mismatched Host/port/SNI, spoofed forwarded headers, anonymous/outside/operator credentials, query tokens, GET-to-mutation variants, and cross-device/project handles cannot read. Include an explicitly authenticated paired request that hits the hard-disabled gate. Use deterministic barriers between prepare, admission, and first write for grant removal, revocation and cancellation; assert no pre-commit status/content leaks, partials are discarded after commit, and a second device makes progress under a slow first one. No live credentials or state.

## Prototype direction for a supported filesystem mechanism

If a Linux deployment becomes useful, use `openat2` as a reference path, not an implementation claim for this Mac:

- Pin a verified approved root, then resolve each complete descendant name in a **single syscall** relative to that root, with `RESOLVE_BENEATH | RESOLVE_NO_SYMLINKS | RESOLVE_NO_MAGICLINKS | RESOLVE_NO_XDEV`. Use `O_PATH | O_CLOEXEC` to classify without activating nodes. No downgrade on unsupported flags, kernel, or filesystem. A bounded retry can handle a transient race error; otherwise report stale/unavailable.
- Compare the metadata descriptor against the opaque handle's identity, file type, link count and revision. For regular bytes, research a same-object reopen through a **verified, private procfs descriptor directory**, never a process-supplied path; the live `O_PATH` descriptor must stay owned and referenced through reopen and the read descriptor must revalidate. No procfs, no reopen. Validate this mechanism before adopting it. Enumeration likewise must use only a checked directory descriptor and classify entries beneath the pinned root.
- Preserve current API/auth, deny hidden entries, keep caps/timeouts and revocation, do not add global shares or write to the source tree. Never send a newly selected object's bytes with an older handle. Existing binary contract/API and the independent iOS fixture need not change.

## Acceptance matrix before removing a platform gate

- On the supported OS/filesystem, record runtime version, mount type, and required syscall behavior. Successful listing/reads must use the same approved binding and live revision; unsupported platform/kernel/fs errors must deny when a grant exists.
- Mount fixtures in an isolated disposable VM: cover nested mounts (including same-filesystem bind mounts where applicable), remount/replacement of the approved root, and transitions concurrent with resolution. Require kernel denial before activation, not just a late revision mismatch.
- Driver/target trace or instrumented helper: assert there is no byte-bearing open on an unclassified object, including regular-to-FIFO/special-file substitution. Verify directory/file leaf and intermediate rename/symlink substitutions, short reads, changed revisions, and no final committed body on cancellation or revocation.
- All fixtures use generated scratch data. Outside/operator/query/alias auth and distinct-device handle rejection stay covered. No real binding, Mac mount changes, real pairing, or shared simulator is needed.

`ProjectFilesTests` exercises deterministic Kestrel/scratch cases; it is not a mount-race proof. Run `dotnet test tests/Marten.Tests --filter FullyQualifiedName~ProjectFilesTests` on arm64 Darwin for the prototype regression suite.
