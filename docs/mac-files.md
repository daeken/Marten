# Read-only Mac Files (native API)

Mac Files is **off by default**. The boot-time host setting `"macFilesEnabled": true` opts all active paired devices into browsing the Mac as the account running Marten. Use this only when you trust every paired credential with that account's readable files. A bearer is not physical-device attestation. Files may include private data, credentials, backups and agent/runtime state; revoking a device cannot recover a copy or invalidate separately usable credentials read from disk. There is no project grant or folder allowlist.

Requires non-root Marten on Apple silicon with macOS 26 or newer, and the [embedded tailnet HTTPS helper](embedded-tailnet.md) built from a revision that supports the Files startup handshake. The default-off setting retains the previous helper startup handshake. An older helper rejects the Files startup mode; there is no fallback to other HTTPS proxies. The canonical name must match TLS SNI and HTTP Host. The helper strips incoming proof headers, adds the private per-start proof only on exact canonical GET Files/status requests received on that TLS listener, and forwards over loopback. Kestrel requires that proof and an active paired `Authorization: Bearer …` credential. A local web/operator session, outside-agent token, direct loopback request with the canonical Host, direct private HTTPS pairing without the embedded helper, or a forwarded header is not enough. No browser/PWA, outside-agent, or public Files route is added.

## Wire contract

`GET /api/status` advertises optional top-level `"macFiles": true` only to an active paired bearer over verified canonical native TLS on an enabled, supported server. The key is omitted otherwise. Do not probe roots to discover capability. `macFilesEnabled` is loaded at startup; changing it does not change a running process. Disabling and restarting cuts off future Files requests, not earlier copies or other credentials read from disk.

All calls are `GET` under `/api/mac-files`; no query, `Origin`, `Range` or caller-supplied path. Only the server generates opaque handles (exactly 32 lowercase hexadecimal characters). The JSON below uses placeholders for handles and time.

| Route | Successful response |
| --- | --- |
| `/roots` | `[{"id":"<directory handle>","label":"Mac"}]` for filesystem root `/`. |
| `/entries/{handle}` | `{"entries":[{"id":"<handle>","name":"example","directory":false,"bytes":123,"modified":"<UTC RFC3339>"}],"next":"<cursor>"}`. Accepts a root, directory, or cursor. `bytes` is absent or null for directories; `next` is absent or null on the last page. |
| `/bytes/{handle}/text` | Exact prefix `min(observed size, 256 KiB)`. No encoding check or conversion. |
| `/bytes/{handle}/raster` | Entire observed file, at most 8 MiB. No decoding or media-type inference. |
| `/bytes/{handle}/share` | Entire observed file, at most 32 MiB. No conversion or server-side export. |

All successful byte responses use `application/octet-stream`, `Content-Disposition: attachment` (no filename), exact `Content-Length`, `Cache-Control: no-store` and `X-Content-Type-Options: nosniff`. JSON responses are also not cacheable. A client should discard incomplete transfers and not trust file contents as executable or rendered markup. There is no write, auto-export, archive, preview execution, indexing, or content spool. Read-only means no intentional write to the source filesystem; reads may update access time or cause ordinary OS/filesystem activity (e.g. automount, file hydration).

Hidden and physically mounted trees are eligible where macOS and the effective account allow access. Marten does not elevate or bypass POSIX permissions, macOS privacy controls, or sandboxing. Symbolic links are never followed. Finder aliases are not resolved; an alias file may appear as an ordinary file with its own bytes. Special files are skipped; known device/pseudo/automount filesystem types (`devfs`, `fdesc`, `procfs`, `autofs`), invalid or misleading names, and unrepresentable paths (over 1,000 UTF-8 bytes relative to root) are excluded. Scope is owner-trusted: same-UID processes, the admin and the local mount namespace are not adversaries this route isolates. Descriptor/revision checks reject ordinary replacements and changes, but do not offer a filesystem snapshot, detect every same-metadata mutation or remount, or make file opens immune to a hostile privileged concurrent device substitution or stalled filesystem.

The supported access model is regular files and directories on trusted, behaving filesystems, including ordinary mounted storage; there is no volume allowlist. Before either pathname open, Darwin metadata lookup rejects a stable FIFO, socket, device node, or symlink. The second open uses nonblocking/no-tty, no-symlink and (for directories) directory-only flags, and the returned descriptor is revalidated before use. This is **not** an atomic regular-file-only acquisition: the metadata check and open are separate. The trust assumption is that ordinary file and directory edits may race, but a device node or an untrusted driver/mount is not substituted mid-lookup. Filesystems with trigger mounts, synthetic nodes, hydration or remote I/O may transform lookups or stall; there is no guarantee of non-activation or hard timing on them. The filesystem-type check is descriptor-based and can occur only after the metadata probe. Stale selections fail rather than retrying against a replacement.

Each page emits at most 100 rows and examines at most 256 names from a held directory stream, in filesystem scan order across pages (rows within one page are directories-first, then ordinal by name). Empty pages can have a `next` when candidates were filtered or the previous page ended at its budget. When `next` exists, send it as the next `/entries/{handle}` unchanged. A continuation is single-use; if a reply was lost, restart the listing. Handles are bound to the issuing credential and expire three minutes after issuance. Directory handles can refresh the same object; cursors bind the directory revision and the position, and file handles bind the observed file revision. Directory and cursor handles never read file bytes. Refresh on missing/expired/stale handles.

Admission uses one in-flight operation per credential and four total, without queues or per-device reservations. Data staging is memory-only, at most 32 MiB per staged byte response. The catalog holds at most 2,200 handles per credential and 4,096 globally. New pages can evict the oldest non-cursor handles to keep progressing above those limits. At most two retained directory streams per credential and eight globally are kept, plus at most one tentative new stream per active request. Each stream holds at most two descriptors. Expired positions are unusable, and idle expired or revoked streams are reclaimed on the next admitted request or shutdown. Work and any stream cleanup remain charged to capacity until they return. The 20 s application budget is cooperative around synchronous filesystem calls; an unresponsive filesystem can keep a slot and its descriptors until the syscall returns.

Typical failures are empty: `401` for a missing or invalid paired credential at the native authority; `403` for an inadmissible request or inactive credential at publication; `404` for disabled/unsupported Files or invalid, expired or wrong-type handles/purposes; `409` for replaced, changed or no longer readable content; `413` for an oversized whole-file operation; `416` for ranges; `429` for admission or retained-stream limits; `503` for a pre-publication deadline. Other routing/authentication failures can happen earlier. No success is sent until bounded staging completes and publication wins the same gate as authoritative credential removal. Revocation before commit denies publication. Revocation after commit aborts an active response; it cannot retract bytes already handed to the transport, delivered, or saved by the client.

## Scratch validation

Run `dotnet test tests/Marten.Tests --nologo -v:q -m:1 --filter FullyQualifiedName~MacFilesTests -- RunConfiguration.MaxCpuCount=1 xUnit.ParallelizeTestCollections=false`. To include the real loopback TLS proxy-to-Kestrel control on supported Macs, build the Go test binary to a private temporary directory (`go test -tags 'ts_omit_logtail ts_omit_oauthkey ts_omit_identityfederation ts_omit_peerapiserver' -c -o /absolute/private/temp/proxy-fixture` from `src/Marten.Tsnet`) and set `MARTEN_MAC_FILES_PROXY_FIXTURE` to that binary for the .NET command. The fixture uses a synthetic certificate and isolated scratch homes, not a real tailnet, an installed helper, or a full Program startup integration. It verifies truncation after the first 64 KiB chunk by revoking the active credential during a paused 4 MiB response through Go. The Go suite separately exercises the actual startup proof parser and EOF lease reader with an in-memory pipe (disabled, malformed/partial input, fragmented proof, then EOF).
