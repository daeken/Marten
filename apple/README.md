# Marten for iPhone and Mac

This is the first milestone of a native **operator** client, not a read-only/outside-agent client. It has SwiftUI screens on iOS 17+ and macOS 14+ and no embedded web UI. Full web capability parity is the target; see the checklist below for what is missing.

## Build and run

Open `apple/Marten.xcodeproj` in Xcode (verified with Xcode 27). Select **Marten-iOS** for an iPhone simulator or **Marten-macOS** for My Mac. The checked-in project is generated from `apple/project.yml`; after adding or removing files, use `xcodegen generate --spec apple/project.yml` from the repository root. Running or testing an existing checkout doesn't require XcodeGen.

```sh
xcrun simctl list devices available
xcodebuild -project apple/Marten.xcodeproj -scheme Marten-macOS -destination 'platform=macOS' test
xcodebuild -project apple/Marten.xcodeproj -scheme Marten-iOS \
  -destination 'platform=iOS Simulator,name=iPhone 17' test
```

Install a simulator runtime from Xcode > Settings > Components if the destination list is empty (or `xcodebuild -downloadPlatform iOS`). For physical iPhone development:

1. Connect the unlocked phone to the Mac, accept the trust prompts, and enable Developer Mode on the phone if Xcode requests it.
2. In Xcode > Settings > Accounts, select your own Apple ID/team. In **Marten_iOS > Signing & Capabilities**, use automatic signing with your development team. If necessary, set a unique bundle ID locally. Do not commit team IDs, personal bundle IDs, provisioning files, or signing changes.
3. Select the phone and run the **Marten-iOS** scheme. This verifies signing and launch; new-device pairing is not available in this build.

## Connect and use

- **New device pairing is disabled**, including in the optional embedded build. The in-app iPhone camera and macOS/iOS image import, exact-origin confirmation, redemption, and recovery are wired behind an injected enrollment adapter; the shipped app does not supply one. There is no credential-bearing URL scheme or production manual-connect path. Use Debug loopback to exercise the MVP.
- Saved servers use their own Keychain credential. iOS uses a device-only item available when unlocked; macOS uses the local login Keychain and may ask for access after rebuilding an ad-hoc app. Preferences contain origins only: saved servers, the current selection, and any pending local cleanup. **Disconnect** retains the credential and any committed node for reconnect. **Forget** removes the local bearer and, in the gated embedded flow, invalidates the session, closes the node, and deletes its private state before removing the saved server. Incomplete cleanup leaves a retryable entry that cannot reconnect or re-pair. After cleanup, use a fresh pairing QR. Forget is not remote revocation: use the server or Tailscale admin controls to revoke the bearer or remove the tailnet device, respectively. Builds without an enrollment adapter cannot complete embedded Forget and leave the saved entry intact.
- Select a project filter or view all open agents; tap an agent for its transcript and composer. Use **Older** and **Newer** beside the composer to browse archived pages, **Latest** to return to the current timeline, and **Agent Actions** for refresh, pause/resume, and interrupt. Status and latest transcript update while active (8s and 4s polling after each response). The gated WSS path adds coalesced refresh hints and in-progress conversation text and activity through the same embedded transport. Latest follows while you are near the bottom; scrolling away or opening an archive stops following. There is no background fetch. A failed send retains the draft and is not retried automatically; check the transcript before resending if the connection dropped.
- Transcript previews support headings, inline Markdown styling and fenced code. Tool output can include images; use **Load Attached Image** to fetch a bounded, static preview through the current Bearer-authenticated route. The app does not fetch images or open links from transcript Markdown.
- **Inbox** shows messages and waiting-question counts, and links to available source agents. Answer questions in Inbox or in the agent’s transcript with a listed option, an option plus an optional note, or your own words. Saved answers come from the server. If a submission fails, the app keeps the draft and reads the current question state before enabling another manual submission; reconnect never replays an answer.
- **Messages Between Agents** shows newest-first history, with a project filter, source and destination agent links, timestamps, delivery mode and reason. It reads the existing operator message history; it does not send agent-to-agent messages.
- Debug builds also have **Connect to Loopback** for a scratch server only, with an HTTP origin on `127.0.0.1` (`localhost` is normalized to that literal) and a scratch UI token. Use a separate `MARTEN_HOME` and port, e.g. set `{"port":17450}` in its `config.json`; never paste a production token there. This connects to the Mac from its simulator, but on a physical phone loopback is the phone itself. The Release app has no manual credential entry and won't load saved HTTP endpoints.

The production endpoint validator accepts only the exact lowercase `https://<device>.<tailnet>.ts.net` origin, on implicit port 443 and without a trailing slash. The gated confirmation shows the offered authority before enrollment and keeps it unchanged for HTTPS and WSS thereafter. The HTTP client uses an ephemeral URLSession with platform TLS validation, no redirects (even same-origin), and no credential in request URLs. It doesn't display request/response dumps. `Transport` is injectable. The gated embedded adapter uses one authenticated loopback SOCKS proxy with failover disabled. Its transport rejects noncanonical or different authorities before using URLSession. It never falls back to the system route.

The v2 QR is raw JSON, not a URL: integer `v: 2`, `server`, `code` (43 base64url characters), `expiresAt` (UTC, milliseconds and `Z`), and `tsAuthKey` only in embedded mode. The connection mode is explicit before scan, so a missing key cannot switch embedded pairing to direct HTTPS. After confirming the exact server, embedded enrollment uses the Tailscale key separately and only then redeems the Marten code with unauthenticated `POST /api/pair/redeem`, `{code, deviceName}`. Follow-up operator requests use the per-device bearer in `Authorization` only.

## Optional embedded transport build (staged)

The normal project builds without the SDK. For review of the adapter, build upstream `tailscale/libtailscale` at `dacde75057ff350e146505829beff446e6823966` with Go 1.27.4 and Xcode 27. Run `make c-archive-ios c-archive-ios-sim c-archive` at the pinned checkout root. From its `swift/` folder, build Release schemes `TailscaleKit (iOS)`, `TailscaleKit (Simulator)`, and `TailscaleKit (macOS)` with destinations `generic/platform=iOS`, `generic/platform=iOS Simulator`, and `platform=macOS,arch=arm64` respectively (`-derivedDataPath build CODE_SIGNING_ALLOWED=NO`). Use `xcodebuild -create-xcframework` with the three built `TailscaleKit.framework` slices from `build/Build/Products/{Release-iphoneos,Release-iphonesimulator,Release}`. Place or link the result locally at `apple/.local/TailscaleKit.xcframework` and run `xcodegen generate --spec apple/project-embedded.yml`, then open `apple/MartenEmbedded.xcodeproj`. Never commit the local path, framework, or generated embedded project. The optional project targets arm64, iOS 18.1+ and macOS 15.6+ and embeds the framework; it does not add a VPN entitlement.

The adapter keeps node state in private, backup-excluded per-origin Application Support directories (0700; iOS file protection) and keeps the Marten bearer separate in Keychain. The caller must commit node state only after confirmed redemption and Keychain persistence; reconnect reopens committed state without the enrollment key. On foreground the staged adapter probes its local SOCKS listener. A confirmed connection refusal replaces the node and session using the same committed state; an ambiguous probe failure stops workspace traffic and shows a connection error. This probe does not establish that the remote server is reachable. The workspace keeps its navigation and drafts when the route changes, and requests are not replayed. Authenticated events use only `wss://<same-authority>/api/events` and the Bearer header; socket and polling tasks stop when inactive. Synthetic tests exercise confirmation, persistence, reconnect, request wiring, Forget retry after relaunch, and re-pair with a fresh QR. The optional embedded Mac tests also exercise deletion of committed fixture state without opening a node. These tests do not exercise live-node shutdown, a real WebSocket handshake, or Tailscale enrollment. Real enrollment, WSS through the embedded node, camera and suspend/resume still need end-to-end checks before activation. The default and embedded macOS tests, unsigned iOS device build, and simulator SDK test build pass. CoreSimulator refused to install/launch the test app because the iOS 27 runtime path was missing. The earlier non-embedded MVP passed on an iPhone 17 simulator; no physical-device enrollment was attempted.

Parity means matching the actions and outcomes available to an operator, not cloning the layout or reusing React. The paired credential is intended to have full operator authority; missing controls below are product gaps, not role restrictions. Server-admin and destructive tests should run only against isolated scratch data.

Operations use the existing Bearer-authenticated routes. An open log refreshes roughly every two seconds while visible and active, requests the last 200 lines, and accepts up to 1 MiB of plain text. Stop and remove each require confirmation; the client rereads the list after an attempt and does not replay mutations on reconnect. The client checks the selected schedule’s creation timestamp against the displayed list before sending, but the server deletes by numeric ID without an atomic version check. A concurrent operator or agent can still remove and replace a schedule in that window. Synthetic fixtures cover the wire models, authenticated request paths, log validation, and read-only reconciliation after an uncertain mutation. Native navigation, confirmation dialogs, and actual stop/removal effects have not been tested interactively against a scratch server or on a device.

Notebook responses are capped at 32 MiB each; exports must be Jupyter notebook JSON with the server’s notebook MIME type. The save picker receives local bytes, not a URL or credential. Rerun requests have a three-minute client deadline; timeout or cancellation does not prove that the server command did not run. After an unconfirmed result, the app requires a fresh notebook read before another explicitly confirmed run; it never retries a rerun automatically. Synthetic fixtures cover the recorded and rerun state, confirmation cancellation, cancelled and failed requests, read-only reconnect, and request authorization and export validation. Native confirmation, the save picker, and actual server rerun effects have not been exercised interactively.

The new creation and lifecycle controls use existing Bearer-authenticated operator routes. Close and Start Fresh Context require confirmation tied to the current route and selection. After a submission the app rereads status, never replays the mutation, and requires a fresh read if reconciliation fails. Synthetic fixtures cover payloads, paths, authentication, history attribution, confirmation cancellation, conflict and read-only reconnect. Actual project creation, pause/close effects, context reset, and interactive navigation/dialogs have not been exercised on a scratch server or device.

Guard cards distinguish one-time call approval from script review and require a confirmed explicit choice, with an optional note. The call card shows the server’s argument preview and rule, not full structured arguments; approval applies to the requesting agent’s next identical call. Script review uses the server’s stored version reference; a changed script is not approved or removed by a decision on an older card. The server’s answer record confirms the decision was saved, not that the reviewed script was still current. Settings sends both model and effort, with explicit null for defaults, and refreshes status afterward. Approval and settings mutations are never replayed. Synthetic fixtures cover approve/deny, version matching, API failures and read-only reconnect; live effects and native dialogs are unverified.

Provider key drafts exist only in the secure field and are cleared on submit, cancel, navigation, backgrounding, or route change. New values travel in the authenticated request body only; status does not return keys and the app discards raw upstream sign-in errors. Reconciliation reads status without replaying mutations. The current ChatGPT authorization flow binds its OAuth callback to `127.0.0.1` on the server host, and the login URL can contain an ID-token hint. Remote sign-in needs a backend-supported flow that neither depends on the client reaching that callback nor exposes provider tokens in a URL delivered to the phone. Fixture coverage does not verify live provider changes, sign-out effects or secure field interactions.

Outside-client token paths refer to files on the Marten server, not usable paths on the phone. Native does not fetch tokens, rotate them, or change Apple pairing. Removal rechecks the displayed creation timestamp locally; the server still deletes by name without an atomic version check. Backup passphrases are submitted in a pinned authenticated request body and not retained by the app; changing encryption does not rewrite existing snapshots. Admin mutations reconcile by reading status without replay. Synthetic fixtures cover routes, authorization, redaction, cancellation and read-only reconnect; UI and real server effects were not exercised.

Suggested order: (1) daily operation — rich timeline refinements, collapsible project navigation; (2) projects and observability — version-bound direct tool review if a matching operator endpoint becomes available; (3) settings/admin — remote provider sign-in when the backend supports it. At each milestone exercise the same operation as web on a scratch server, test failure and destructive confirmations, and check iPhone layout/VoiceOver and macOS keyboard navigation. End-to-end HTTPS redeem and camera/Tailscale checks on a physical iPhone are separate from unit and simulator tests.
